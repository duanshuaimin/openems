01 // CONTROL THEORY

控制论基石：双速率级联经济模型预测控制 (Dual-Rate Cascade EMPC)

不同于化工过程控制中以稳态工作点跟踪（Setpoint Tracking）为目标的二次型 MPC，储能能量管理系统属于典型的 经济模型预测控制 (Economic MPC, EMPC)——其目标函数直接衡量分时购电成本、余电上网收益与电网需量越限惩罚，且同时包含离散控制模式（充电/锁电/自平衡）与连续功率变量。

PILLAR 01 · PREDICTION MODEL

可组合黑盒状态转移模型

传统线性 MPC 要求将所有被控对象简化为状态空间矩阵 $\mathbf{x}_{k+1} = A\mathbf{x}_k + B\mathbf{u}_k$。而 OpenEMS 通过 EnergyScheduleHandler 接口允许每个设备（储能、充电桩集群、热泵、算力负载）注册独立的 Java 前向仿真函数 simulate()，在 EnergyFlow.Model 中精确求解非线性功率边界与削峰限流。

PILLAR 02 · RECEDING HORIZON

变步长滚动时域与热启动

每 15 分钟重构一次 GlobalOptimizationContext，采用 前 6 小时 15 分钟高分辨率 (`Quarter`) + 远期 60 分钟聚合 (`Hour`) 的变步长时域，并通过 InitialPopulationUtils 将上一周期最优解左移一步注入初始种群，实现经典 MPC 热启动 (Warm-Start)。

PILLAR 03 · FEEDBACK CORRECTION

仅执行首步 $u_0^*$ + 1Hz 纠偏

外环优化出的未来 24 小时模式序列中，仅有第 0 个周期 getCurrentPeriod() 被下发给 TimeOfUseTariffControllerImpl。内环在每个 1000ms 扫描周期根据实测电网功率与实时 SoC 动态修正充放电设定值，彻底吸收预测偏差。

STOCHASTIC ROBUSTNESS · ENVIRONMENT.JAVA

价格弹性三次方风险膨胀函数 (Risk-Adjusted Consumption)

在动态电价尖峰时刻，负荷预测偏低比偏高具有强烈的不对称经济惩罚（一旦电池提前放空，系统将被迫以全天最高电价从电网买电）。OpenEMS 在 Environment.java#L10-L15 与 PeriodsBuilder.java#L250-L260 中对归一化电价 $\tilde{\pi}_{\text{buy}}(k) \in [0, 1]$ 施加三次方风险裕度：

p_norm(k) = (π_buy(k) - π_min) / (π_max - π_min) ∈ [0, 1]
E_cons_risk(k) = round( E_cons_actual(k) × [ 1.0 + 0.2 × p_norm(k)³ ] )

• 谷电时段 ($\tilde{\pi}_{\text{buy}} = 0$)：膨胀因子为 $1.00$，按无偏预测值调度；
• 平段电价 ($\tilde{\pi}_{\text{buy}} = 0.5$)：膨胀因子为 $1.025$（仅增加 $2.5\%$ 缓冲）；
• 尖峰电价 ($\tilde{\pi}_{\text{buy}} = 1.0$)：膨胀因子跃升至 $1.20$（预留 $20\%$ 安全放电裕度），确保电池锁住足够电量穿越价格洪峰。

NEGATIVE PRICE HANDLING · PERIODSBUILDER.JAVA

负电价区间正平移变换 (Positive Price Shifting)

欧洲电力现货市场（如 Entso-E、Awattar）经常出现负电价（$\pi_{\text{buy}} < 0$）。若直接将负电价代入购电成本公式 $\text{Cost} = E_{\text{buy}} \cdot \pi_{\text{buy}}$，加上 $1.17$ 损耗系数后会导致负数乘法方向反转，甚至诱导优化器无意义地损耗买电。为此 PeriodsBuilder.calculatePositiveShift() 执行保序正平移：

Δ_shift = |π_min| + (π_max - π_min) / 2.0 (当 π_min < 0)
π_shifted(k) = π_buy(k) + Δ_shift > 0

该变换严格保持了全天不同时段电价的相对差价序关系，同时确保 “不从电网买电（Cost = 0）”永远优于任何非必要的损耗性电网买电行为。

ENERGYFLOW.MODEL · PER-STEP SOLVER

单步能量守恒与边界钳位状态机

在每一个预测步 $k$，EnergyFlow.Model.from(gsc, period) 先根据当前可用电量 $x_{\text{ess}}(k)$ 与逆变器最大功率计算单步充放电能量上限：

E_ess_maxCharge(k) = min( P_maxCharge × Δt_k, E_total - x_ess(k) )
E_ess_maxDischarge(k) = min( P_maxDischarge × Δt_k, x_ess(k) )
E_surplus(k) = E_prod(k) - [ E_unmanaged(k) + Σ E_managed_m(k) ]

当控制器调用 ef.setEss(target) 时，模型自动将其钳位在电网最大买电/卖电功率与储能物理边界构成的四维可行域内，并由 ef.solve() 一步闭合电网交换量 $E_{\text{grid}}(k)$ 与弃光量 $E_{\text{excess}}(k)$。

MULTI-ASSET COMPOSABILITY · ESH

多类柔性资产统一协同调度接口

OpenEMS 的 MPC 并非仅针对单一电池，而是将全站所有实现 EnergySchedulable 的组件编排进同一条时间步流水线：

1. 储能系统 (Controller.Ess.Time-Of-Use-Tariff)：决策 `BALANCING` / `DELAY_DISCHARGE` / `CHARGE_GRID` / `LIMIT_CHARGE` / `DISCHARGE_GRID`；
2. 智能充电桩集群 (Controller.Evse.Cluster)：通过 JointModes 联合优化多枪充电模式（`MINIMUM` / `SURPLUS` / `FORCE`），并在 SingleScheduleContext 中追踪每辆车的累计充入电量 $x_{\text{evse}}(k)$；
3. 电制热与柔性算力 (Heat.Askoma / Heat.MyPv / BraiinsOs)：通过 ef.addManagedConsumption(id, target) 在低谷电价或光伏消纳期动态开启热泵与算力负载。

MPC WARM-STARTING · INITIALPOPULATIONUTILS.JAVA

三大先验种子注入与滚动时域热启动

遗传算法在純随机初始化下收敛较慢。OpenEMS 在 InitialPopulationUtils.generateInitialPopulation() 中构造了确定性热启动种群：

1. 全自平衡基线 (generateAllDefault)：全时域基因置为 `0` (`BALANCING`)，确保优化器保底性能不低于传统自发自用控制器；
2. 上一周期最优解平移 (getScheduleFromPreviousResult)：按时间戳映射上一轮 15 分钟周期求出的最优模式序列 $\{u_1^*, u_2^*, \dots\}$，在滚动窗口推进时直接继承历史演化成果；
3. 电价波谷启发式探针 (findValleyIndexes)：自动识别未来电价曲线的所有局部极小值点，生成单点 `CHARGE_GRID` 与 `DELAY_DISCHARGE` 探针基因笛卡尔积。

REAL-TIME GUARANTEE · SIMULATOR.JAVA

30 秒首步基因锁定与后台持续求精

为了防止在 15 分钟周期内因为遗传算法不断发现微弱改进而导致当前正在执行的控制模式反复跳变，Simulator.runOptimization() 实现了精妙的两阶段提交机制：

if (!isCurrentPeriodFixed && Instant.now().isAfter(start + 30s)) {
  onBestResult.accept(bestSchedule);
  isCurrentPeriodFixed.set(true); // 锁定 k=0 基因 u₀*
}

在周期开始后的前 30 秒（或配置变更重调度时），进化引擎全力搜索包括当前周期 $k=0$ 在内的全局最优解；一旦满 30 秒，立即发布首步决策并将 isCurrentPeriodFixed 置为 `true`——此后解码器 EshCodec 强制将第 0 步固定为已发布模式，而后台 `N-1` 个低优线程继续演化未来时段 $k \ge 1$ 直至收敛 (Limits.bySteadyFitness(500))，为下一轮滚动热启动储备最优轨迹！

06 // ARCHITECTURAL EVALUATION

架构横向评测：仿真驱动混合进化 MPC vs 传统 MILP/QP 凸优化 MPC

为什么 OpenEMS 在外环 MPC 中选择基于 io.jenetics 的仿真驱动混合进化算法，而在 1000ms 内环中选择基于 SimplexSolver 的精确线性规划？这一“外环进化寻优 + 内环凸规划保底”的混合架构体现了极高的工业工程成熟度。

核心评估维度 OpenEMS 外环：仿真驱动进化 MPC (Jenetics + EnergyFlow) 传统学院派：混合整数线性/二次规划 (MILP / MIQP) OpenEMS 工程决策背后的深层逻辑
插件化与第三方扩展性 极高 (Black-Box Composable)：新设备仅需编写普通 Java 方法描述单步物理行为即可接入全局优化 低 (White-Box Monolithic)：每增加一种设备（如热泵、矿机）都必须重写全局矩阵组装器 OpenEMS 拥有 200+ 硬件模块，黑盒仿真接口让硬件工程师无需具备运筹学背景即可开发预测调度能力
非线性与离散状态机表达 原生零失真：直接支持死区阈值（8.1% 最小充电电流）、非线性损耗、条件分支状态后处理 (postProcessMode) 需大量 Big-M 松弛与 0-1 变量：离散模式切换与最小运行功率极易引发分支定界树指数级膨胀 储能逆变器在低功率区的效率坍塌与模式切换逻辑天然是非凸、非连续的
