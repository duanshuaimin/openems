# OCMS 首期开发计划：接入、监控、告警与工单闭环

> 版本：1.1 · 2026-10-17；状态：开发执行基线，尚未实现或完成联调。
>
> 执行说明：按任务使用 executing-plans 技能实施；每个任务先固定契约和失败用例，再实现、验证、评审并独立提交。本文不授权直接切换生产环境。

**目标：**完成“租户建站 → 设备接入 → 实时与历史监控 → 告警 → 工单验收”，覆盖设计阶段 0–3。

**架构：**OCMS 独立部署，通过直接读写公共 PostgreSQL 和 OpenEMS B2B API 集成。公共租户资产主数据统一管理，OCMS 业务库独立；Backend 持久化运行事件，OCMS 执行业务判定。

**技术方向：**Java 21、Spring Boot、Vue 3、TypeScript、ECharts、PostgreSQL、InfluxDB；精确依赖版本由 T01 的兼容性证据锁定。

**设计依据：**[OCMS 协同设计 v2.2](../../../openems_cloud_management_design.md)、[现有通信接口](../../../OPENEMS_EXTERNAL_AND_ODOO_INTERFACES.md)。本文补充原设计中尚未确定的实施细节；所有新增默认值都是工程选择，不代表现网已验证能力。

## 1. 全局约束与交付边界

- 已确认首期范围为阶段 0–3，允许必要的 Backend 与网关适配；远程组件配置、通道控制、调度、收益结算留到下一期。
- 生产首期一个区域、一个集群、一个活动 Backend、一个活动 OCMS；故障后重启恢复，不承诺高可用无中断。测试使用两个集群验证身份和时序隔离。
- 公共管理模块部署在 OCMS 中，Metadata.Tenant 使用同一身份与授权源；原生 UI 公共管理写入口接入同一规则或关闭。
- OCMS 写管理字段，Backend 写运行观测；原始遥测仅由采集链路写入。跨库使用 inbox/outbox 和幂等，不使用跨库事务。
- 每集群默认独立 Influx bucket；存储映射包含实例/组织、bucket、measurement 和数字标签。现有标签保留，同一存储范围内禁止数字标签复用。
- 公共库与业务库均使用事务级租户上下文、RLS 和非所有者应用账号。父子租户默认不继承权限，代管显式授权。
- 后端使用 Maven Wrapper；前端使用 pnpm 锁文件；数据库迁移使用版本化 SQL 和 Flyway。OSGi 适配器沿用锁定 OpenEMS 源码的构建链，不向其中装入 Spring 运行组件。
- 首期通知为站内通知和 SMTP 邮件，附件保存在独立持久目录，通过鉴权接口访问；邮件外部投递为至少一次语义。
- 本计划按依赖和退出条件安排，不承诺未经人员与环境核验的工期。M0 后根据任务清单估算排期，不以压缩验收范围换取进度。

### 重点评审条件

| 条件 | 必须保证 | 责任任务 |
| --- | --- | --- |
| 数据库慢、队列满或进程退出 | 接入线程不被事件写库阻塞；缓冲有界；缺口可识别 | T09 |
| 活动故障期间修改规则 | 不伪造恢复，不重复创建同一规则版本周期 | T10 |
| 连接正常但通道陈旧 | 缓存重复推送不能延长源数据有效期 | T07、T10 |
| 网关已有新密钥但现场未更新 | 不宣布轮换完成；截止期按明确策略处理 | T06 |
| 旧系统持续修改或切换后回滚 | 权限变更不遗漏，撤销凭据不恢复 | T03、T12 |

## 2. 工程划分、契约与依赖

在 `ocms/` 下建立 platform-contracts、tenant-domain、tenant-jdbc、ocms-server、ocms-web；在 `openems-adapters/` 下维护 metadata-tenant、Backend 事件挂点和 gateway-apply-adapter。上游改动保存为可应用于锁定 commit 的补丁系列，并通过 CI 验证可重建，不依赖服务器未提交修改。

任务中列出的接口是项目新增契约，不是已存在的 OpenEMS 方法。T01 固定协议与 DDL 草案，T02 将其转为可构建制品；后续变更需同步消费者与契约测试。

| 契约 | 生产者 → 消费者 | 必需语义 |
| --- | --- | --- |
| AssetLocator | 资产模块 → 监控/时序/事件 | asset_id、tenant_id、cluster_id、remote_edge_id、存储定位；先授权再解析 |
| ChannelContract | 点表适配 → 监控/告警 | 通道、单位、类型、状态等级、上报模式、采样间隔、freshness_limit、时间证据类型、配置版本 |
| ChangeEvent / ApplyReceipt | 公共管理 → Metadata/网关 → 操作查询 | event_id、aggregate_id、revision、consumer_id、consumer_epoch、应用与连接处理结果；无明文密钥 |
| RuntimeEvent / RuntimeGap | Backend → OCMS | 资产、producer_epoch、asset_sequence、类型、occurred_at 可空、observed_at、配置版本、载荷；缺口包含原因及区间 |
| TelemetrySample | B2B 适配 → 监控/阈值规则 | value、source_timestamp 可空、source_observed_at 可空、received_at、quality、connection_epoch |
| AlarmOccurrence | 告警 → 通知/工单 | tenant_id、asset_id、rule_id、rule_version、occurrence_id、信号/处置状态、评估终止原因和证据 |
| MigrationManifest | 迁移工具 → 发布/回滚 | run_id、源标识映射、快照/增量边界、差异、凭据版本与撤销清单；不含明文秘密 |

北向接口沿用设计的 `/api/v1/tenants`、`sites`、`edges`、`operations`、`alarms`、`work-orders`，增加登录/退出、规则版本和附件接口；历史与门户 WebSocket 返回时间及质量。写接口要求幂等键；修改已有资源校验 revision，创建操作校验唯一性。相同主体、资源、幂等键和载荷重试返回原结果，载荷不同返回冲突。首期不提供任意 RPC 透传或控制命令入口。

依赖顺序：T01 → T02 → T04 → T05 → T06 为开站主链；T03 从 M0 开始贯穿迁移；T07/T08 依赖身份与资产契约，先对测试环境实现；T09 依赖 T05，T10 依赖 T07/T09，T11 依赖 T10，T12 汇总发布验收。前端可按契约使用模拟响应开发，里程碑验收必须连接真实服务。

## 3. 里程碑与开发任务

### M0：契约、环境与可执行验收基线

#### T01：锁定版本和集成契约

**交付：**完整源码 commit、JAR 校验值、组件配置、依赖版本锁、能力矩阵、点表、OpenAPI/事件 schema、DDL 草案及验收配置。

- [ ] 获取目标部署证据，验证文档中的 `01083d6` 与实际 JAR 对应关系；当前工作区不具备该源码时不能把文档记录作为已通过结果。
- [ ] 建立隔离环境：两个租户、两个测试集群和同名 edge0、不同 bucket；不得运行现有演示脚本向生产库写数据。
- [ ] 验证 B2B 认证、角色、订阅替换、2 秒快照、null、配置回传、历史口径与查询饱和；输出可重跑测试和脱敏报文。
- [ ] 定位 Backend 原始通道接收挂点、网关凭据版本识别/回执/断开接口；确定补丁位置、构建步骤和兼容性用例。
- [ ] 按第 4 节冻结通道新鲜度和持久事件契约；完成第 5 节验收参数文件。所有必填值均有数值、单位及理由，不保留 TBD。
- [ ] 制定身份密码迁移规则：只有通过真实样本认证测试的哈希格式允许导入，否则执行强制重置；旧登录会话统一失效，设备密钥保持不变。

**退出：**上述制品可评审、测试可运行；一站接入/订阅/历史链路通过。未具备的能力已有明确可测试适配任务；没有关键接口签名、数据结构或验收阈值悬空。

#### T02：工程与验证入口

**交付：**可构建骨架、公共契约制品、双数据源、迁移交付物、CI 和测试夹具。

- [ ] 实现统一错误、UUID、revision、时间与质量类型；业务事件协议不依赖 Spring。
- [ ] 建立按模块的单元/集成测试，以及两个数据库、Influx 和模拟 Edge 的集成环境。
- [ ] 建立独立迁移账号，验证应用账号无法 DDL、跨租户查询或越权更新；连接池每事务设置并自动清理上下文。
- [ ] 提供稳定入口：`./mvnw -f ocms/pom.xml verify`、`pnpm --dir ocms/ocms-web test`、`pnpm --dir ocms/ocms-web build`；上游适配器构建命令记录在版本锁清单并接入 CI。

**退出：**空库初始化、重复迁移、契约序列化和前后端构建通过；以上命令是待创建工程的验收入口，不代表当前仓库可直接运行。

#### T03：迁移工具与同步策略（跨 M0–M3）

**交付：**只读源抽取、幂等导入、差异校验、最终同步、反向同步、撤销保护和演练报告。

- [ ] M0 盘点 Odoo 用户、设备、授权、配置、密钥及源外键；为每类记录建立稳定源 ID → UUID 映射，角色映射逐项核验。
- [ ] M1 实现 `extract / import / diff / finalize / reverse / verify` 六个工具子命令；支持 dry-run、run_id 和重复执行，同一源记录不生成新 UUID。
- [ ] 试运行期间 Odoo 为唯一管理源，OCMS 管理写关闭。每次核验使用一致性全量快照进行差异同步，显式处理删除与撤权，不能只按更新时间增量扫描。导入与变更事件在公共库事务内提交。
- [ ] 只读试运行使用部署在旧系统的受限服务身份访问 B2B；最终用户的设备访问按当前 Odoo 授权复核，复核失败拒绝。不得仅用延迟镜像授权用户访问。旧源授权适配器在切换后停用。
- [ ] 切换时冻结旧公共管理写入口与源权限修改，完成最终全量差异和数量/引用/凭据校验，再切换 Metadata；运行状态不纳入管理冻结。
- [ ] M3 演练写入后回滚：冻结新管理写，抽取切换后的完整变更，转换旧库可接受结构，应用撤销清单再校验。不能无损反向表达的记录使回滚失败，保持维护态并修复前进，不能默默丢弃。
- [ ] 旧库曾存明文的设备密钥经受控通道导入后加密存储；导出物、报告不含秘密。凭据撤销审计独立备份，恢复前与旧快照比对。

**退出：**首次导入、重复导入、删除/撤权、密码重置、冻结前最后一次变更和写入后回滚全部可重跑验证；未完成 T03 不进入生产只读试运行。

### M1：公共底座与开站闭环

#### T04：身份、租户、资产和数据库隔离

- [ ] 实现登录/退出、会话撤销、租户层级、成员、站点、设备、服务身份和设备授权；父子租户可见性显式配置。
- [ ] 资产登记校验 site/tenant 一致性、远端名称和数字标签唯一性；首期不支持跨租户/跨集群转移。
- [ ] 管理修改、registry 投影、脱敏审计、change_event 与目标投递同事务提交，返回 operation_id。
- [ ] 业务表保存 tenant_id；同库关联采用租户一致性约束，跨库资产引用由授权查询校验。异步任务执行、导出下载和附件访问均重新校验权限。
- [ ] 验证幂等冲突、并发 revision、租户上下文缺失、池复用、平台特权审计及所有列表/详情入口隔离。

**退出：**管理 API 和基本管理页面可用；只有授权范围内的用户可登记、查看与管理资产。

#### T05：Metadata.Tenant 与可靠应用

- [ ] 实现 Metadata、B2B 认证、设备角色映射、冷启动加载及运行字段写入。
- [ ] 实现逐消费者投递、租约、重试、revision 去重、tombstone、周期对账及新消费者快照衔接；不用全局最大 sequence 代表消费完成。
- [ ] 验证并发写入全量加载、应用后确认前退出、重复/逆序事件和旧进程写入拒绝；producer_epoch 在启动时持久分配。
- [ ] 将原生 UI 公共管理写入口接入公共模块或关闭；验证 OCMS 停机不终止既有采集。

**退出：**对象版本可从数据库追踪到 Backend；所有配置快照明确为观测数据，不能被管理端直接覆盖。

#### T06：网关确认与现场密钥轮换

- [ ] 实现网关版本回执及连接使用的 credential_version 观测，不在日志和回执传输密钥明文。
- [ ] 正常轮换流程为：生成新版本 → 所有目标网关确认接受 → 授权安装人员安全领取 → 现场更新 → 目标 Edge 使用新版本认证成功 → 撤销旧版本 → 网关与旧连接处理确认。
- [ ] 首期使用经重新认证的受审计 HTTPS 领取入口，秘密不通过邮件、工单附件或日志发送；安装人员从现场管理通道更新 Edge。丢失领取结果可重新签发新版本，不提供一般列表接口读取密钥。
- [ ] 操作记录增加 FIELD_UPDATE_PENDING、NEW_KEY_OBSERVED 和异常原因；人工“已更新”勾选不能替代新版本握手证据，网关无法识别版本时必须补适配。
- [ ] 默认正常轮换窗口 24 小时；到期无新版本证据转 MIGRATION_OVERDUE 并告警，仍按已声明截止时间撤销旧密钥，设备可能离线，不能伪报轮换完成。延期须在截止前显式受审计修改，已撤销密钥不能复活。
- [ ] 紧急撤销不等待现场迁移，立即推动旧版本拒绝新握手及存量连接断开，之后执行受控恢复。
- [ ] 缓存可用期为最后成功对账后 5 分钟，超期拒绝新握手；Backend 冷启动不可用旧凭据文件回退。
- [ ] 验证现场未更新、错误设备握手、部分网关未确认、截止任务重启、断网和旧备份恢复。

**退出：**登记至上线及正常/紧急轮换闭环通过；APPLIED 必须包含要求的凭据版本与连接处置证据。

### M2：监控、历史与隔离

#### T07：实时客户端与门户

- [ ] 按集群/只读服务身份/分片管理 B2B 连接，每资产只有一个采集订阅归属；全量替换订阅并递增 count，重连重新授权。
- [ ] 单活动 OCMS 内维护快照和门户推送；部署使用互斥租约防止重启重叠，失去租约立即停止订阅发布和告警评估，旧代次结果被拒绝。
- [ ] 落实第 4.2 节质量状态，撤权关闭门户订阅；展示时间、质量、在线状态、配置只读信息。
- [ ] 交付站点列表、单站概览、能量流和设备状态；缺少电芯点位时展示已有聚合层级。
- [ ] 验证相同值重复快照、正常心跳但通道停更、连接重建、null、乱序、权限撤销和跨租户订阅。

**退出：**真实通道可正确展示；新鲜度不足不能作为告警恢复证据。

#### T08：历史查询与异步报表

- [ ] 实现直查 Influx 与 API 对照两个适配器，使用授权 AssetLocator 和固定查询模板。
- [ ] 统一单位、本地日历日期转换、[start,end)、累计量重置、缺失、稀疏保持与聚合；不静默回退查询口径。
- [ ] 限制资产/通道/点数和并发，报表使用持久任务；客户端超时后退避，对照服务不可用时熔断。
- [ ] 在隔离环境复现文档记录的 REST 队列挂起。客户端超时不视为释放服务端线程；若目标版本确认该缺陷，补拒绝任务的 future 异常完成和服务端等待上限，或关闭生产 REST 历史对照入口，生产发布默认采用修复并验证后的适配制品。
- [ ] 验证两个 edge0、标签冲突、时区/夏令时、跨日、重置、稀疏数据、导出撤权，以及过载解除后服务端线程和请求能力恢复。

**退出：**历史口径对照通过；超载不会通过重试持续放大，服务端恢复有证据。

### M3：告警、通知与工单闭环

#### T09：Backend 运行事件与背压

- [ ] 在 Backend 接收选定状态通道处挂接事件，连接与汇总事件走同一规范化接口；具体故障不能仅依赖汇总等级触发下钻。
- [ ] 按第 4.1 节实现独立有界缓冲、独立连接池、批量事务、幂等重试、缺口和启动代次；不在接入线程执行 JDBC 或等待队列空间。
- [ ] OCMS inbox、告警变化和通知 outbox 同业务事务提交后再确认公共库；支持回放、去重、资产内顺序及当前快照对账。
- [ ] 默认保留 30 天；未确认事件不静默删除，强制清理先落缺口。来源中断、队列溢出和异常退出按保守区间声明未知。
- [ ] 注入数据库故障、队列满、事务提交响应丢失、进程强杀、重放确认丢失；验证采集继续、内存有界、缺口和重复事件处理正确。

**退出：**仅对已经持久化的事件承诺可重放；无法重建的区间有明确记录，不能宣称正常。

#### T10：规则版本、告警与通知

- [ ] 实现原生状态、离线、阈值、数据质量四类规则，按第 4.2/4.3 节管理质量、时间、防抖和版本。
- [ ] 保存规则有效区间、旧版本评估终止原因、故障周期和新旧关联；规则编辑与逻辑切换事件同业务事务提交。
- [ ] 重放使用事件时间对应的规则版本；发生时间不可靠时使用 observed_at 并标明依据，不能跨版本混算防抖。
- [ ] 历史已恢复周期补建但不逐条实时通知；恢复后仍活动的告警只产生一次延迟发现通知。
- [ ] 实现站内通知与邮件 outbox；重试采用相同逻辑幂等键，发送结果不明时记录可能重复，外部邮件不宣称 exactly-once。

## 4. 审阅问题的确定性补充

### 4.1 事件写入与故障边界

- 首期每活动 Backend 使用一个有界 FIFO 队列和一个写入 worker，事件在资产锁内分配 asset_sequence 并入队，跨资产无需全局有序。大配置事件只含引用/哈希，完整配置走独立快照写入。
- 测试默认双限额 10,000 条/32 MiB，以先触及者为准；单条规范化事件不超过 16 KiB。超限拒绝入队，不阻塞采集，不丢弃已有排队事件；拒绝结果计入 gap。
- 独立事件连接池默认 2 个连接，单批最多 200 条或等待 100 ms；数据库获取/语句超时默认 2 秒。失败以相同 event_id 重试，退避 1、2、4、8、16、30 秒并加抖动，不无限增加在途批次。
- 写入运行摘要和对应事件在同一事务完成，摘要仅接受较新代次/序号。提交结果未知时重试相同事件，不能重新编号；事件唯一键保证去重。
- 队列或载荷溢出时在固定大小的每集群 gap 累加器保存最早/最晚受影响时间，恢复后优先持久化 RuntimeGap；按集群扩大未知范围，避免为每次丢失分配无限内存。
- 定期保存完整覆盖检查点，只有检查点前已接受事件全部持久化且丢失区间已记录才推进。检查点周期测试默认 5 秒。异常启动从最后检查点到新启动完成建立保守缺口，不假定尚在内存的事件已落库。
- 数据库失联期间无持久化能力，内存 gap 也可能丢失；重启缺口从旧检查点推导，保证不误报完整。首期不增加磁盘 WAL，允许有明确标记的事件损失。

### 4.2 新鲜度与持续阈值

- ChannelContract 区分 PERIODIC、CHANGE_ONLY、UNKNOWN。PERIODIC 只有源采样时间或 Backend 实际收到该通道样本的时间可作为新鲜度证据；后者须以适配字段提供给 OCMS。
- 新鲜度默认上限为 `max(3 × 约定上报间隔, 10 秒)`，M0 按实际通道验证并固化。重复 B2B 缓存快照只更新 received_at，不更新源证据时间。
- CHANGE_ONLY 只有经过验证的采集质量/有效期或读取到设备当前采样值的主动查询才能维持 GOOD；普通 getEdgesChannelsValues 缓存读取及连接心跳不算新证据。缺少证据则 UNKNOWN，并禁止依赖它做持续阈值判定。
- 数值非法为 INVALID，已有可靠样本超过新鲜度限额为 STALE，无足够证据为 UNKNOWN；只有 GOOD 可推进触发或恢复防抖。
- 阈值规则定义为离散有效样本下的持续超限：至少两个有序源观测，间隔不超过约定上限，覆盖配置的防抖时间。相同源样本的重复快照不推进窗口。该规则不证明样本间不存在物理瞬态。
- UNKNOWN/STALE/INVALID、连接代次变化和 gap 均清空未完成窗口；已活动告警保留未恢复事实并转信号 UNKNOWN。重新获得 GOOD 后建立新的触发/恢复窗口。

### 4.3 规则变更与活动告警

- rule_id 稳定，版本不可变且有效区间不重叠；唯一活动评估键为 `(tenant_id, asset_id, rule_id, rule_version, channel)`。
- 规则修改/禁用时停止旧版本继续评估，记录 `evaluation_end_reason = SUPERSEDED / DISABLED` 和结束时间，信号转 UNKNOWN 并保留 last_known_signal；不设置 recovered_at，不自动关闭处置状态或工单。
- 新版本重新建立防抖窗口，不能继承旧版累计时长。满足触发条件后创建新 occurrence，以 supersedes_occurrence_id 关联旧周期；每新版本周期只发送一次明确标注“规则变更后触发”的通知，旧周期不发送恢复通知。
- 旧周期可由授权人员结案并记录“规则替换/停用”，但这不算设备恢复。历史重放只在旧版本有效区间内评估；迟到证据可修正该区间的历史，并记录修订，不延长旧规则有效区间。
- 计时排序以可信 occurred_at 为先，否则 observed_at；事件序号用于资产内顺序。来源时间倒退或不可信时标记质量问题，不用异常时间计算 MTTA/MTTR。

## 5. 验收矩阵、通过阈值与发布门禁

### 测试默认配置

以下是固定的初始测试配置，用于建立可执行门禁，不是生产容量承诺。T01 将设备点表、环境规格和实际参数写入验收配置；若必须调整，保留变更理由并在开发前冻结，不能测试失败后直接降低门槛。

| 项目 | 初始配置/通过条件 |
| --- | --- |
| 基准负载 | 100 个模拟资产、每资产 50 通道、每 2 秒一个样本；20 个门户连接；连续 60 分钟 |
| 历史查询 | 5 个并发查询，每次 1 资产/10 通道/7 天/5 分钟聚合，输出点数受限 |
| 时延 | 源观测可用时门户端到端 p95 ≤ 5 秒；历史查询 p95 ≤ 5 秒；告警不含配置防抖的附加延迟 p95 ≤ 5 秒 |
| 元数据生效 | 健康环境所有必需目标 p95 ≤ 10 秒；任何目标未确认不得 APPLIED |
| 事件故障 | 在运行负载下数据库失联 10 分钟并注入队列溢出；事件缓冲不超过配置条数/字节上限；采集和 Edge 心跳继续 |
| 写库恢复 | 数据库恢复后 60 秒内恢复提交及缺口可见，固定 10,000 条积压在 5 分钟内排空，无重复业务周期 |
| 瞬态故障 | 只对 Backend 实际收到并持久化的发生/恢复变化验收重放；两次 B2B 快照间被上游遗漏的变化不计承诺 |
| REST 过载 | 客户端有界超时；部署修复后服务端等待也有界，压力解除 60 秒内服务恢复且线程占用回落，无无限重试 |
| 恢复与回滚 | 测试环境从备份至可查询、可鉴权恢复目标 30 分钟；已提交凭据撤销不得因恢复丢失 |

门户控制台、数据库、日志中不得出现完整密码/密钥；平台监控至少包含各级应用时延、队列占用与拒绝数、gap、事件积压、陈旧通道、通知失败和数据库等待。

| 验收场景 | 责任任务 | 通过证据 |
| --- | --- | --- |

发布顺序为测试环境 → 只读试点 → 管理切换 → 告警/通知 → 工单。每个门禁须有测试结果与失败归因；未达标保留为未完成，不将“已编写测试”视作“已通过”。
