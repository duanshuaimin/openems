02 / MICROKERNEL

OSGi 声明式微内核：为什么用“Nature 正交接口”取代继承树？

在能源系统中，一台混合逆变器可能同时是“对称储能（SymmetricEss）”、“三相不平衡储能（AsymmetricEss）”、“直流光伏充电器（EssDcCharger）”和“Modbus 从站（ModbusSlave）”。传统单继承层次必然陷入组合爆炸，OpenEMS 用 OSGi Declarative Services + Nature 多接口正交组合 给出了教科书级解法。

LAYER 01 OSGi Runtime
Apache Felix SCR + ConfigAdmin 动态生命周期

通过 @Component 与 @Designate(ocd = Config.class, factory = true) 将每個硬件实例映射为一条 OSGi Factory PID 配置记录（持久化于 /etc/openems.d/*.config），支持毫秒级热插拔与参数重绑定。

LAYER 02 Nature Contract
正交领域契约（Nature Interfaces）

每个硬件组件按能力实现多个 Nature 接口（如 ElectricityMeter、ManagedSymmetricEss、Evcs）。控制算法仅通过 @Reference 注入抽象 Nature，与底层是正泰电表还是施耐德电表彻底解耦。

LAYER 03 ChannelId & Doc
自描述静态通道契约（Self-Describing Channels）

每个 Nature 内部包含 enum ChannelId，在类加载期通过 Doc.of(OpenemsType) 绑定物理单位、读写权限、报警级别与初始值，并在 AbstractOpenemsComponent 构造器中自动反射实例化全部通道。

LAYER 04 OsgiValidateWorker
依赖拓扑自检与故障挂起守护

ComponentManagerImpl 内置后台守护线程 OsgiValidateWorker，持续比对 ConfigAdmin 配置与 SCR 激活状态；一旦发现硬件失联或引用悬空，立即置位 _componentManager/State = FAULT。

03 / PROCESS IMAGE

PLC 级双缓冲过程映像：彻底消灭多线程数据撕裂（Data Tearing）

工业微电网中，Modbus RTU 串口轮询、TCP 异步套接字、HTTP 气象拉取运行在数十个独立 I/O 线程中。若控制器在计算中途读取到被半途覆写的电表功率，将导致防逆流或削峰控制产生剧烈震荡。OpenEMS 在 AbstractReadChannel.java 中实现了严格的双缓冲过程映像（Process Image）。

BUFFER A // ASYNC I/O WRITE ZONE

volatile Value<T> nextValue

所有异步硬件线程（ModbusWorker、HttpBridge、模拟器）随时调用 channel.setNextValue(v) 写入最新采样值。

  • 触发 onSetNextValueCallbacks（用于底层瞬时抓包）
  • 对业务控制器完全不可见，绝不干扰正在执行的控制周期
  • 无锁 volatile 引用替换，零阻塞 I/O 线程
nextProcessImage() Cycle 扫描起点
原子切换屏障 T = 0 ms
BUFFER B // DETERMINISTIC CONTROL SNAPSHOT

volatile Value<T> activeValue

在每个扫描周期的 Switch to Channels 阶段，nextValue 被原子晋升为 activeValue，并在整个周期内保持只读冻结。

  • 写入环形时间序列缓存 TreeMap<LocalDateTime, Value<T>> pastValues
  • 触发 onUpdateCallbacks 与 onChangeCallbacks
  • 保障同一周期内所有控制器读取到严格同源的时间断面

private volatile Value<T> nextValue = new Value<>(this, null);
private volatile Value<T> activeValue = new Value<>(this, null);
private final TreeMap<LocalDateTime, Value<T>> pastValues = new TreeMap<>();

@Override
public void nextProcessImage() {
    var oldValue = this.activeValue;
    var newValue = this.nextValue;
    this.activeValue = newValue; // 原子冻结当前扫描周期的过程映像断面
    var now = LocalDateTime.now();
    this.pastValues.put(now, newValue);
    this.pastValues.headMap(now.minusSeconds(MAX_SECONDS_TO_KEEP_PAST_VALUES)).clear(); // 自动裁剪过期窗口
    this.onUpdateCallbacks.forEach(callback -> callback.accept(newValue));
    if (!Objects.equals(oldValue.get(), newValue.get())) {
        this.onChangeCallbacks.forEach(callback -> callback.accept(oldValue, newValue));
    }
}

05 / OPTIMIZATION

快慢双擎运筹大脑：Simplex 线性规划功率分配 vs Jenetics 遗传进化调度

OpenEMS 将能源优化拆解为两个正交的数学问题：在毫秒级实时周期内，用单纯形法（Simplex）在多台逆变器的物理极限多面体中求解可行工作点；在日前 24 小时尺度内，用遗传算法（Genetic Algorithm）搜索非线性电价与损耗下的全局最优控制序列。

REAL-TIME ENGINE // io.openems.edge.ess.core.power.v1.Solver

Simplex 线性规划与 4 级策略降级瀑布

当多个控制器同时作用于储能系统（例如：上级调度要求放电 $\ge 200\text{kW}$，而变压器防过载控制器要求放电 $\le 500\text{kW}$，BMS 限制最大功率 $\le 450\text{kW}$），所有指令被转化为关于各逆变器三相有功/无功向量 $\mathbf{x} = [P_{i,L1}, P_{i,L2}, P_{i,L3}, Q_{i,L1}, Q_{i,L2}, Q_{i,L3}]^T$ 的线性约束集：

Minimize / Maximize: cᵀ · x
Subject to: A_eq · x = b_eq , A_ineq · x ≤ b_ineq
Bounds: P_min,i ≤ P_i ≤ P_max,i , S_i² ≥ P_i² + Q_i²
  • S1OPTIMIZE_BY_KEEPING_ALL_EQUAL：优先尝试令集群内所有逆变器严格均分功率，降低局部热应力。
  • S2OPTIMIZE_BY_KEEPING_ALL_NEAR_EQUAL：若各柜 SoC 或限额不同导致严格均分无解，放宽为近似均分。
  • S3KEEP_TARGET_DIRECTION_AND_MAXIMIZE_IN_ORDER：保持总充放电方向不变，按逆变器优先级顺序依次打满（提升轻载时单机转换效率）。
  • S4ZERO_FAILSAFE_FALLBACK：若硬约束冲突导致 NoFeasibleSolutionException，自动回退至 getZeroSolution() 安全零功率停机。
HORIZON ENGINE // io.openems.edge.energy.optimizer.Simulator

Jenetics 遗传算法与 CPU 物理核隔离机制

针对分时电价套利（TimeOfUseTariff）与充电桩有序排程，由于电池效率折算（源码常量 EFFICIENCY_FACTOR = 1.17，对应 ~85.5% 往返效率）与状态转移具有强非线性，系统采用 io.jenetics 演化引擎对未来 15 分钟时间片（Quarters）进行全局仿真寻优：

Chromosome: G = [m₀, m₁, ..., m_{N-1}] (m_t ∈ ModeCombinations)
Fitness: F(G) = (HardViolations, GridCost + ModePenalty, SoftRunLengthCost)
Hyperparams: PopSize=300 | Mutator=0.05 | ShiftMutator=0.20 | Crossover=0.20
  • C1N-1 物理核隔离与最低线程优先级：availableProcessors() - 1 且绑定 Thread.MIN_PRIORITY，确保高负载进化计算绝不抢占 1000ms 实时控制周期的 CPU 时间片。
  • C230 秒渐进式首周期锁定（Progressive Locking）：运算满 30 秒（earliestCallbackDelay）立即发布当前最优解并置位 isCurrentPeriodFixed = true，锁定当前 15 分钟基因，继续深度演化后续时段。
  • C3500 代稳态收敛截断：通过 Limits.bySteadyFitness(500) 自动检测收敛平台期，兼顾求解质量与边缘工控机功耗。

private void assignConsumptionChannels() {
    var ess = this.essHandler.getActivePower();      // +放电 / -充电
    var grid = this.meterHandler.getGridActivePower(); // +买电 / -卖电
    var prod = this.meterHandler.getProductionAcActivePower(); // +光伏发电

    // 1. 节点有功功率严格守恒：P_load = P_ess + P_grid + P_pv
    var consumptionPower = IntUtils.sumInteger(ess, grid, prod);
    setValue(this, Sum.ChannelId.CONSUMPTION_ACTIVE_POWER, consumptionPower);

    // 2. 非受控基础负荷剥离：P_unmanaged = P_load - P_managed(EVCS/HeatPump)
    setValue(this, Sum.ChannelId.UNMANAGED_CONSUMPTION_ACTIVE_POWER,
        TypeUtils.subtract(consumptionPower, this.meterHandler.getManagedConsumptionActivePower()));

    // 3. 累计电能守恒：E_cons = (E_ess_dis + E_grid_buy + E_pv) - (E_ess_chg + E_grid_sell)
    var enter = TypeUtils.sum(this.essHandler.getActiveDischargeEnergy(),
        this.meterHandler.getGridBuyActiveEnergy(), this.meterHandler.getProductionAcActiveEnergy());
    var leave = TypeUtils.sum(this.essHandler.getActiveChargeEnergy(),
        this.meterHandler.getGridSellActiveEnergy(), this.meterHandler.getProductionAcActiveEnergyNegative());
    var consumptionEnergy = Optional.ofNullable(enter).orElse(0L) - Optional.ofNullable(leave).orElse(0L);
    this.energyValuesHandler.setValue(Sum.ChannelId.CONSUMPTION_ACTIVE_ENERGY, consumptionEnergy);
}
SIGN RULE 01 Grid Meter
电网表符号约定（Grid Convention）

从电网购电（下网）定义为正值 $P_{\text{grid}} > 0$，向电网馈电（上网）定义为负值 $P_{\text{grid}} < 0$。

SIGN RULE 02 ESS Storage
储能符号约定（Load/Generator Convention）

储能向母线放电定义为正值 $P_{\text{ess}} > 0$，从母线吸收功率充电定义为负值 $P_{\text{ess}} < 0$；含混合逆变器时自动区分 AC 侧视在功率与 DC 侧实际功率。

07 / FIELDBUS

工业现场总线桥接：CycleTasksManager 五态同步状态机

RS485 串行总线与工业 Modbus TCP 设备普遍存在响应慢、半双工冲突及偶发超时问题。OpenEMS 在 io.openems.edge.bridge.modbus 中设计了精巧的周期同步五态机，使慢速异步串口与 1000ms 主扫描周期实现严密咬合。

STATE 01

INITIAL_WAIT

在 BEFORE_PROCESS_IMAGE 触发时装载本周期读写队列，并阻塞等待当前周期的控制器完成计算。

STATE 02

WRITE

收到 EXECUTE_WRITE 事件后立即唤醒 waitMutexTask，以最高优先级将 FC6/FC16 控制指令下发至逆变器。

STATE 03

WAIT_BEFORE_READ

由 WaitDelayHandler 动态计算最佳休眠等待时长，将读取窗口精准推迟至下一周期的采样前沿。

STATE 04

READ

依次执行全部 Priority.HIGH（每周期必读功率）与 1 个轮转 Priority.LOW（温度/序列号等慢变量）读取任务。

STATE 05

FINISHED

本周期总线事务完毕。若下一周期起点仍未进入此状态，自动触发 CycleTimeIsTooShort 告警并熔断隔离超时从站。
