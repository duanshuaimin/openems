1. 架构总览与启动流水线

在通用微服务开发（如 Spring Boot）中，应用通常拥有一个显式的入口主类与方法 public static void main(String[] args)。但在 OpenEMS Edge 工业微电网控制系统 中，为了支持储能变流器（PCS）、电表、BMS、充电桩等 200 余类硬件驱动的动态热插拔、故障隔离与零停机重载，OpenEMS 采用了 OSGi (Open Services Gateway initiative) 微内核规范 与 bnd 构建体系。

2. JVM 命令行与 Fat-JAR 结构

在 Linux 部署环境下，Edge 以 systemd 守护进程运行。通过查验 /etc/systemd/system/openems-edge.service： 

[Unit]
Description=OpenEMS Edge (Open Energy Management System)
After=network.target

[Service]
Type=simple
User=root
WorkingDirectory=/opt/openems
ExecStart=/usr/bin/java -Dfelix.cm.dir=/etc/openems.d/ -jar /opt/openems/openems-edge.jar
Restart=always
RestartSec=5
LimitNOFILE=65536

解包分析 /opt/openems/openems-edge.jar 的 META-INF/MANIFEST.MF：

Manifest-Version: 1.0
Embedded-Runpath: jar/org.apache.felix.framework-7.0.5.jar,jar/biz.aQute.launcher-7.4.0.jar
Main-Class: aQute.launcher.pre.EmbeddedLauncher

Main-Class 引导装载器

真正的入口是 aQute.launcher.pre.EmbeddedLauncher，负责构建包含 OSGi 容器核心与 bnd 运行时的类加载器环境。

-Dfelix.cm.dir 配置注入路径

指向持久化配置落盘目录 /etc/openems.d/，包含系统出厂预设和用户在运行时动态添加的所有组件 .config 文件。

内嵌 Bundle 库 (jar/)

包含 Guava、Netty、Pax Logging 以及 OpenEMS 的 200+ 个业务模块 JAR，作为一个完整的独立微内核分发。

3. 引导器与 OSGi 容器自举

自举阶段包含三个紧密耦合的步骤：

  1. EmbeddedLauncher.main(args)： 创建自定义类加载器，动态加载 Embedded-Runpath 中的 org.apache.felix.framework-7.0.5.jar 与 biz.aQute.launcher-7.4.0.jar，随后反射调用执行 aQute.launcher.Launcher.main(args)。
  2. Launcher.main(args) 与 launcher.properties： 读取内置在 JAR 根目录下的 launcher.properties，将系统属性（如 java.awt.headless=true、felix.cm.dir）注入 JVM。
  3. 实例化与启动 Apache Felix 框架： 调用 new Felix(configMap) 创建 OSGi Framework 实例，执行 framework.init() 初始化 Bundle 缓存空间，最后执行 framework.start()。

4. StartLevel 分级加载时序

在拥有数百个组件的系统中，若并发启动将不可避免地造成死锁或配置缺失错误。OpenEMS 在 EdgeApp.bndrun 中规划了严密的分级启动级别（StartLevel）：

StartLevel Bundle 核心模块 系统职责与架构关键作用
Level 10 org.apache.felix.scr Service Component Runtime (SCR)：声明式服务引擎，扫描各 Bundle 的 OSGi-INF 元数据，管理 @Component、@Reference 生命周期。
Level 11 org.apache.felix.configadmin Configuration Admin：自动读取 /etc/openems.d/*.config 并与对应组件 PID 绑定，触发组件属性注入。
Level 12 org.apache.felix.eventadmin Event Admin：OSGi 事件总线，支撑微电网 TOPIC_CYCLE_* 周期节拍广播。
Level 13-14 fileinstall / metatype 配置文件动态热监控与组件配置元数据描述服务。
Level 15-16 pax-logging-api / log4j2 统一日志切面，保证后续业务类能够正常输出 SLF4J / Log4j2 日志。
Level 17 io.openems.core.referencetarget 动态重写组件的 @Reference(target="...") 过滤条件，支持复杂的硬件端口与服务动态路由。
Level 18 io.openems.core.logger 动态日志级别调节器，依据 ConfigAdmin 配置动态更新运行中包名的 Debug/Info/Warn 级别。
Level 19 io.openems.edge.application 应用入口宣告组件（EdgeApp）。
Level 20+ io.openems.edge.core 及所有业务组件 加载 ComponentManager、Sum、Cycle、通信协议桥（Modbus/HTTP/CAN）与算法调度控制器。

5. 业务启动宣告 (EdgeApp)

在 StartLevel 19，SCR 自动实例化带有 @Component(immediate = true) 注解的 EdgeApp：

package io.openems.edge.application;

import org.osgi.service.component.annotations.Activate;
import org.osgi.service.component.annotations.Component;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import info.faljse.SDNotify.SDNotify;
import io.openems.common.OpenemsConstants;

@Component(immediate = true)
public class EdgeApp {

    private final Logger log = LoggerFactory.getLogger(EdgeApp.class);

    @Activate
    private void activate() {
        var message = "OpenEMS version [" + OpenemsConstants.VERSION + "] started";
        var line = Strings.repeat("=", message.length());
        this.log.info(line);
        this.log.info(message);
        this.log.info(line);

        // 向 Linux 操作系统宣布 OpenEMS Edge 启动就绪
        var socketName = System.getenv().get("NOTIFY_SOCKET");
        if (socketName != null && !socketName.isEmpty()) {
            if (SDNotify.isAvailable()) {
                SDNotify.sendNotify(); // 向 systemd 发送 READY=1 通知
            }
        }
        this.log.debug("Activate EdgeApp");
    }
}
Systemd Socket 联动

通过 SDNotify.sendNotify()，OpenEMS 与 Linux 底层服务管理器无缝握手。若服务配置为 Type=notify，systemd 将在收到此信号后正式确认服务启动完成，避免了因初始化耗时导致的服务超时杀死问题。

6. 组件中枢与配置注入

在 Level 20+ 阶段，io.openems.edge.core 中枢组件被激活：

  • ComponentManagerImpl (_componentManager)： 使用 TrackedComponentsView 实时监听 OSGi 容器内所有 OpenemsComponent。内部启动 OsgiValidateWorker 持续监控是否所有配置组件都已处于健康 Active 状态；启动 EdgeConfigWorker 维护全站实时 Channel 目录。
  • SumImpl (_sum)： 汇聚所有电表与逆变器功率，实时计算电网购售电、光伏产出、负载消耗与储能 SoC 综合指标。
  • 外部通信服务并发启动： 端口 8095（REST API）、端口 8075（Websocket API）、端口 8080（Felix Web Console）以及向云端 Backend 建立的反向 WSS 长连接通道。

7. 软 PLC 控制循环 (CycleWorker)

OpenEMS Edge 的控制逻辑运行在单例组件 CycleImpl (PID: Core.Cycle) 驱动的 CycleWorker 专有高优先级后台线程 中。每个周期（默认 1000ms）严格执行 9 步标准控制流水线： 

@Override
protected void forever() {
    var stopwatch = Stopwatch.createStarted();

    // 1. 喂系统看门狗（防止硬件死锁挂机）
    this.executeCycleStep(verbosity, CycleLogVerbosity.PHASES, "Notify Watchdog", SDNotify::sendWatchdog);

    try {
        // 2. 触发过程映像更新前事件
        this.triggerEvent(verbosity, EdgeEventConstants.TOPIC_CYCLE_BEFORE_PROCESS_IMAGE);

        // 3. 通道切换到下一个过程映像（Channel.nextProcessImage()）
        // 拍照锁定所有底层传感器采样值，保证本周期内算法读取数据的严格时间一致性
        this.executeCycleStep(verbosity, CycleLogVerbosity.PHASES, "Switch to Channels for each Component",
                () -> Stream.concat(this.parent.componentManager.getEnabledComponents().stream(), Stream.of(this.parent))
                        .filter(c -> c.isEnabled() && !(c instanceof Sum))
                        .forEach(component -> this.triggerComponentEvent(verbosity, component)));

        // 4. 更新 _sum 聚合通道的过程映像
        this.executeCycleStep(verbosity, CycleLogVerbosity.PHASES, "Update the Channels in the Sum-Component",
                () -> {
                    this.parent.sumComponent.updateChannelsBeforeProcessImage();
                    this.parent.sumComponent.channels().forEach(channel -> channel.nextProcessImage());
                });

        this.triggerEvent(verbosity, EdgeEventConstants.TOPIC_CYCLE_AFTER_PROCESS_IMAGE);
        this.triggerEvent(verbosity, EdgeEventConstants.TOPIC_CYCLE_BEFORE_CONTROLLERS);

        // 5. 调度器（Scheduler）按优先级调度所有控制器算法执行
        // 例如：削峰填谷、动态电价平衡、光伏防逆流、充电桩功率限制
        this.executeCycleStep(verbosity, CycleLogVerbosity.PHASES, "Execute Schedulers", () -> {
            var hasDisabledController = this.executeSchedulersWithOptionalMeasure(verbosity);
            this.parent._setIgnoreDisabledController(hasDisabledController);
        });

        this.triggerEvent(verbosity, EdgeEventConstants.TOPIC_CYCLE_AFTER_CONTROLLERS);
        this.triggerEvent(verbosity, EdgeEventConstants.TOPIC_CYCLE_BEFORE_WRITE);

        // 6. 批量硬件写出（EXECUTE_WRITE）
        // 各协议桥（Bridge.Modbus / I/O）将控制器的计算目标值统一批量刷入硬件寄存器
        this.triggerEvent(verbosity, EdgeEventConstants.TOPIC_CYCLE_EXECUTE_WRITE);

        this.triggerEvent(verbosity, EdgeEventConstants.TOPIC_CYCLE_AFTER_WRITE);

    } catch (Throwable t) {
        this.parent.logWarn(this.log, "Error in Scheduler: " + t.getMessage());
    }

    // 7. 耗时统计与防超时监测
    var totalMs = stopwatch.elapsed(TimeUnit.MILLISECONDS);
    this.parent._setMeasuredCycleTime(totalMs);
}
过程映像（Process Image）核心原理

在电力控制系统中，若多个控制器异步读写硬件通道，将引发严重的“脏读”与“控制指令冲突”。OpenEMS 采用 PLC 经典的三段式控制法： 读快照（Snapshot） $\rightarrow$ 纯数学计算（Compute） $\rightarrow$ 集中写出（Write），从而彻底保证了电网调控的原子性与数值稳定性。

8. 架构优势与生产排障指南

为什么不用传统 Spring Boot？

现场工商业储能需要零停机热拔插电表、逆变器等驱动。OSGi 具备严格的模块版本隔离与动态类重载能力，是电力电子边缘侧的首选。

Felix Web Console 可视化诊断

访问 http://<IP>:8080/system/console/components（admin:admin），即可直观查验全站 286 个 OSGi 组件的激活与依赖满足状态。

周期耗时防超时监控

实时监控 Channel _cycle/MeasuredCycleTime。若耗时持续逼近 1000ms，需警惕慢 Modbus 阻塞调用，应将耗时 IO 转入异步线程。
